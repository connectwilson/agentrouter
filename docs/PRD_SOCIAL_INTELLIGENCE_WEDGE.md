# AgentRouter Social Intelligence Wedge

日期：2026-07-21

## 战略结论

相比链上数据，跨社交平台的内容研究更可能形成高频 PMF。目标用户不是“需要 API 的 Agent 开发者”，而是持续寻找选题、验证观点和理解受众的内容创作者、Founder、内容团队与社媒经理。

AgentRouter 不应直接销售“API 路由”。前台产品应销售一个结果：

> 输入一个观点、选题或目标受众，返回来自 X、Reddit、小红书等平台的真实讨论、支持与反对证据、痛点频率、内容空白和可追溯引用。

AgentRouter 作为后台数据平面，负责发现数据源、按平台和任务路由、控制成本、处理失败、标准化内容、去重、标注来源与授权状态。

## 为什么这个需求更强

内容工作流具备 AgentRouter 所需的五个条件：

1. **高频**：选题和内容验证每天或每周发生。
2. **跨源必要**：单看 X 容易偏向即时观点，Reddit 更适合长讨论，小红书反映中国消费与生活方式语境。
3. **长尾动态**：每次研究的关键词、人群、语言和平台组合不同，无法全部提前写死。
4. **结果可验证**：用户需要原帖、时间、互动量和上下文，而不是无来源的 AI 总结。
5. **现有方案两极化**：企业 listening 工具贵且复杂，普通创作者仍依赖手工搜索、收藏、复制和 ChatGPT。

## 用户真正购买的任务

### Idea validation

- 这个观点是否真的有人讨论？
- 支持和反对分别来自哪些人？
- 是持续痛点，还是一时情绪？

### Content research

- 最近 7/30 天有哪些反复出现的问题？
- 哪些高互动帖子没有被中文或英文创作者充分解释？
- 同一个话题在 X、Reddit、小红书的叙事有什么不同？

### Audience intelligence

- 目标受众使用什么原话描述问题？
- 他们目前用什么替代方案？
- 哪些内容角度引发收藏、评论或争论？

### Evidence-backed drafting

- 生成内容 brief，但每个论点必须链接到原始帖子。
- 区分事实、用户观点、平台趋势和模型推断。
- 输出“可以说什么”和“证据不足，不能说什么”。

## 推荐产品形态

产品不是传统 social listening dashboard，也不是通用聊天框，而是 Creator Research Terminal。

一次研究应输出：

1. 结论摘要。
2. 支持证据与反对证据。
3. 原始帖子卡片：平台、作者、时间、互动量、原文摘录、链接。
4. 讨论主题与痛点聚类。
5. 跨平台差异。
6. 证据强度和数据覆盖范围。
7. 可采用的内容角度。
8. 尚不能证明的部分。

## AgentRouter 的后台职责

### Capability planning

将用户任务拆成：

- `social_conversation_search`
- `social_post_retrieval`
- `social_trend_detection`
- `audience_pain_point_analysis`
- `cross_platform_claim_validation`
- `creator_content_gap_analysis`

### Provider routing

根据以下条件选择来源或数据供应商：

- 平台覆盖；
- 地区与语言；
- 时间范围；
- 搜索完整度；
- 实时性；
- 原帖链接和互动字段；
- 商用授权；
- 单次成本；
- 历史成功率。

### Canonical schema

统一为 `social_evidence_item_v1`：

- `platform`
- `post_id`
- `canonical_url`
- `author_handle`
- `published_at`
- `retrieved_at`
- `language`
- `text_excerpt`
- `engagement`
- `query_match`
- `thread_context`
- `source_type`
- `license_or_usage_status`
- `provider_id`
- `content_hash`

### Evidence processing

- 跨供应商和转帖去重；
- 保留原文与翻译；
- 区分帖子事实与作者观点；
- 支持/反对证据分组；
- 检测机器人、营销软文和重复文案；
- 明确采样偏差与平台覆盖。

## 数据平台风险

### Reddit

需求已经被 GummySearch 等产品验证，但商业 API 授权变化也能直接杀死产品。必须使用获授权的数据路径，并将 provider fallback 和数据导出作为核心能力。

### X

实时观点价值高，但 API 成本和权限变化明显。不能把毛利建立在固定低价抓取假设上。需要预算路由、缓存、增量更新和多个合规供应路径。

### 小红书

官方开放能力偏营销、多账号和商业场景，公开内容搜索与大规模采集不是天然开放接口。第三方抓取服务存在稳定性、授权、个人信息和内容版权风险。建议在验证英文市场 PMF 后再接入，或先通过用户导出/浏览器辅助采集做私有研究。

### 通用原则

- 不绕过登录、验证码或访问控制。
- 不把“技术上能抓”当作“可合法商用”。
- 每条数据记录授权状态与来源路径。
- 支持删除请求和来源内容下线传播。
- 默认只保存分析需要的最少文本和元数据。

## MVP

### ICP

优先服务每周输出 3 篇以上内容的 B2B/科技/AI 创作者和 Founder-led content 团队。

### 平台

第一期只做 Reddit + X。小红书作为第二阶段独立验证，不要因为“全平台”承诺拖慢上线。

### 核心流程

用户输入：

> “AI Agent 的 API 路由是不是伪命题？查最近 30 天 X 和 Reddit 的真实讨论。”

系统输出：

- 讨论规模和时间变化；
- 主要赞成、反对和怀疑角度；
- 至少 15 条去重后的原始证据；
- 哪些用户属于开发者、创作者、投资人或供应商；
- 3 个有证据支持的内容角度；
- 数据覆盖与无法验证之处。

### 不做

- 自动代发内容；
- 全功能社媒排程；
- CRM 和社媒客服；
- 无来源的一键生成文章；
- 第一版同时覆盖十个平台。

## 商业验证

邀请 20 名每周稳定输出内容的创作者，连续使用 4 周。

衡量：

- 每周完成研究次数；
- 从研究到实际发布的转化率；
- 被采用的证据条数；
- 相比手工研究节省的时间；
- 4 周留存；
- 是否愿意支付 20～50 美元/月。

Go 条件：

- 中位用户每周至少完成 2 次研究；
- 40% 以上研究转化为实际内容；
- 4 周留存至少 40%；
- 至少 30% 测试用户愿意付费；
- 每份报告至少 80% 引用链接在生成时可访问；
- 用户对“证据相关性”的平均评分至少 4/5。

## 对现有 AgentRouter 的调整顺序

1. 暂停继续扩大通用加密 endpoint 数量。
2. 先定义 `social_evidence_item_v1`。
3. 接入 Reddit 与 X 各至少两个合规数据路径。
4. 实现一次研究任务内的多源检索、自动 fallback、去重和引用。
5. 将 trust 从“API 调用成功”改为“证据相关、完整、可访问且被创作者采用”。
6. 前台上线 Creator Research Terminal；AgentRouter 品牌可以保留为底层基础设施。
